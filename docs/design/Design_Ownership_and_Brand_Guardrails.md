## 3. Rules for design changes

1. **Tokens first.** Colours, type and spacing come from `src/styles/tokens.css` (generated by `npm run tokens`; CI checks it with `npm run tokens:check`). Components never hard-code a brand colour or font.
2. **No silent brand change.** Changing the primary colour, the three typefaces, the product name or the token set needs an explicit owner decision recorded in G1-05.
3. **Deviation log.** Any implementation that differs from an approved board is recorded in `docs/design/deviation-log.md` in the pull request that introduces it.
4. **Accessibility.** WCAG 2.1 AA contrast is checked in code (`tests/unit/contrast.test.ts`) and pages are checked with axe in the end-to-end suites. Touch targets are generous (for example the 48 px filter chips, DV-97).
5. **Responsive.** Every screen must work at phone width with the role's mobile navigation. Phone layouts are covered by end-to-end tests such as `tests/e2e/smoke.spec.ts` and `tests/real/notifications-phone-a11y.spec.ts`; new screens add their own.
6. **New screens.** Claude drafts boards on the owner's private design canvas; a board becomes a reference only after the owner approves it (D-32 rule), and it is then listed in `docs/design/missing-screens.md`.
